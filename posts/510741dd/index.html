四、实验原理

1. 查找表和关键字

查找表是由同一类型的数据元素组成的集合。查找时使用关键字与表中元素进行比较，以确定目标元素是否存在以及它在表中的位置。

为了突出查找算法，本实验直接使用整数数组保存关键字：

上面的数组已经按升序排列，可以直接进行折半查找。

查找函数通常有三个输入：数组地址、数组长度和待查找关键字。函数返回的是位置，而不是元素本身。本实验约定位置从 1 开始，返回 0 表示没有找到，这样可以把“第 1 个位置”和“查找失败”区分开。

2. 顺序查找

顺序查找从表的第一个元素开始，依次将数组元素与 key 比较：

  • 如果当前元素等于 key，查找成功；
  • 如果扫描到表尾仍未找到，查找失败；
  • 数组是否有序不会影响顺序查找的正确性。

顺序查找实现简单，适用于数据量较小或数据没有排序的情况。

例如在 3、8、12、17 中查找 12，顺序查找会依次比较 3、8 和 12，第三次比较成功；查找 10 时，必须把所有元素都比较一遍，最后才能确定失败。

3. 折半查找

折半查找要求查找表已经有序。每次取当前查找区间的中间位置 mid 与 key 比较：

  • 如果 a[mid] == key，查找成功；
  • 如果 key < a[mid]，继续在左半部分查找；
  • 如果 key > a[mid]，继续在右半部分查找。

每次比较都可以排除当前区间的一半元素，因此查找范围会快速缩小。

折半查找中的 low 和 high 表示“当前仍有可能找到关键字的区间”。mid 是这个区间的中间下标。每次比较后，必须让区间严格变小，否则可能出现循环无法结束的问题。查找成功时返回 mid + 1，查找失败时是因为 low 已经大于 high。

五、算法设计

1. 顺序查找算法

设置循环变量 i 从 0 开始，依次检查 a[i]。找到关键字后返回 i + 1；循环结束后返回 0。

2. 折半查找算法

设置查找区间的左边界 low = 0 和右边界 high = n - 1。当 low <= high 时，计算中间位置 mid，再根据 a[mid] 与 key 的关系缩小查找区间。

3. 查找结果输出

返回值大于 0 时，将其作为从 1 开始的位置输出；返回值等于 0 时，输出查找失败信息。

4. 输入数据要求

顺序查找可以处理无序数组。折半查找只能用于有序数组，因此在调用折半查找前，应确认数组已经按关键字升序或降序排列，并且算法中的区间调整方向与排序方向一致。

如果数组按升序排列：

  • key < a[mid] 时，目标只能在左半部分，令 high = mid - 1；
  • key > a[mid] 时，目标只能在右半部分，令 low = mid + 1。

这两个方向不能写反。数组未排序时，即使函数能够运行，返回结果也没有可靠意义。

八、问题分析

1. 为什么折半查找要求数组有序

折半查找根据中间元素与关键字的大小关系排除一半查找区间。只有数组有序时，这种排除才是正确的；无序数组不能直接使用折半查找。

2. 顺序查找和折半查找的时间复杂度

顺序查找最好的情况是第一次比较就找到目标，时间复杂度为 O(1)O(1)O(1)；最坏情况需要检查全部元素，时间复杂度为 O(n)O(n)O(n)。

折半查找每次排除一半元素，最坏情况下需要比较 O(log⁡n)O(\log n)O(logn) 次，最好情况下第一次比较就找到目标，时间复杂度为 O(1)O(1)O(1)。

3. 查找失败时如何判断

顺序查找在扫描完整个数组后仍未找到关键字时失败。折半查找在 low > high 时表示查找区间已经为空，此时查找失败。

4. 为什么函数返回位置而不是数组下标

C 语言数组下标从 0 开始，而实验报告通常使用从 1 开始的位置。函数内部可以使用数组下标进行计算，返回结果时加 1，这样更符合实验描述。

5. 什么时候应该选择顺序查找

当数据量较小、数据没有排序、数据变化频繁，或者只需要进行少量查找时，顺序查找实现简单，维护成本较低。当数据已经有序且需要进行大量查找时，折半查找通常更高效。

九、实验总结

本实验要求使用 C 语言完成顺序查找和折半查找的程序框架。顺序查找不要求数据有序，但查找效率与数据规模线性相关；折半查找利用有序性缩小查找范围，具有更好的查找效率。完成各个 TODO 后，可以掌握两种基本查找算法及其适用条件。
