《数据结构》课程大作业任务书

通用硬性要求

0.1 工程结构

  • 必须采用多文件结构，至少包含：main.c + 每个数据结构的 .c / .h 文件（如 list.h / list.c）。
  • 必须提供 Makefile 或 README.md 中的编译运行命令（如 gcc -std=c99 -Wall *.c -o app）。
  • 编译必须零警告（-Wall 下），有警告每项扣 1 分。

0.2 内存与健壮性（重点考察项）

  • 所有动态内存必须 malloc 分配，分配后必须判空。
  • free 之后指针置 NULL，避免野指针。
  • 程序退出前释放所有已分配内存（验收时会用 valgrind 或目测检查 free 配对情况）。
  • 不允许用"足够大的全局数组"代替指定的数据结构。这是本题最核心的考察点，一经发现该项（25 分）直接记 0 分。
  • 程序须能连续交互运行不崩溃：空表删除、满表插入、非法输入（字母输入数字项、超长字符串、负数）均需给出提示并回到菜单。

0.3 交互与输出

  • 数字驱动的循环菜单，形如：

  • 列表输出必须表格化（含表头、对齐的列宽），不得直接打印结构体裸数据。

  • 所有关键操作给出明确的成功/失败反馈。

0.4 代码规范

  • 关键函数必须有注释，格式为：/* 功能 / 参数 / 返回值 / 注意事项 */。
  • 命名统一（推荐 下划线风格 或 小驼峰，全项目保持一致）。
  • 注释率不低于 20%。

0.5 交付清单（缺项不予验收）

# 交付物 要求
1 源码 全部 .c / .h 文件 + 编译脚本
2 测试数据 至少 3 组：正常数据（≥50 条）、空数据、非法/边界数据
3 设计报告 ≥2000 字，格式见 §五
4 演示材料 运行截图 ≥8 张 或 录屏 ≤3 分钟

题目一：学生成绩管理与分析系统（学号 % 3 == 0）

1. 覆盖知识点

线性表（链表/顺序表）· 排序算法 · 查找算法 · 文件持久化 · 简单统计分析

2. 数据定义

3. 存储要求

  • 主存储必须使用带头结点的单向链表，所有增、删、改、查均在链表上完成。
  • 允许在排序时使用临时数组，但不允许用数组作为主存储。
  • 链表节点必须使用 malloc 动态申请。

4. 必做功能

4.1 基本信息管理

  • (1) 批量录入：从键盘或文件一次性录入 ≥50 条学生记录，自动计算总分与平均分。
  • (2) 插入：支持"在指定位置插入"与"按学号有序插入"两种模式。
  • (3) 删除：按学号删除，删除前二次确认。
  • (4) 修改：按学号定位后修改任意字段，并自动重算总分、平均分。
  • (5) 查询：按学号精确查询；按姓名查询（必须支持重名，返回所有匹配项）。
  • (6) 浏览：表格化显示全部学生，含表头与名次。

4.2 统计分析

  • (7) 每门课的最高分、最低分、平均分、及格率（≥60）、优秀率（≥85）。

  • (8) 分数段分布：0-59 / 60-69 / 70-79 / 80-89 / 90-100，用字符柱状图打印，例如：

  • (9) 按总分生成名次（相同分数名次并列，后续名次跳号，如 1,2,2,4）。

4.3 排序（核心考察点）

  • (10) 分别实现 冒泡排序、直接插入排序、快速排序（三选三，均按总分降序）。
  • (11) 每种排序算法必须统计并输出：比较次数、移动（交换）次数、运行耗时（ms）。
  • (12) 输出三种算法的横向对比表，并在报告中给出复杂度分析。

4.4 查找（核心考察点）

  • (13) 对已排序的链表实现二分查找（按学号或按总分二选一，需在报告中说明实现方式）。
  • (14) 实现顺序查找，输出比较次数。
  • (15) 输出"顺序查找 vs 二分查找"在不同数据规模（50 / 200 / 1000 条）下的平均比较次数对比表。

4.5 持久化

  • (16) 启动时自动从 students.dat 加载数据，文件不存在时给出提示并进入空表状态（不得崩溃）。
  • (17) 提供手动保存与退出自动保存。
  • (18) 文件格式（文本或二进制）必须在报告与 README 中说明；能识别并跳过格式错误的记录行。

5. 选做加分项（每项 +2~5 分，总分上限 100）

  • [ ] 追加一个"顺序表版本"，与链表版本做插入/删除效率对比实验，写入报告
  • [ ] 导出 CSV 文件，可直接用 Excel 打开
  • [ ] 撤销功能：用栈保存最近 5 次删除的记录，支持撤销删除
  • [ ] 分页浏览：每页 10 条，支持翻页
  • [ ] 中文姓名按拼音排序（可选简化：仅比较首字）

题目二：停车场管理系统（学号 % 3 == 1）

1. 覆盖知识点

顺序栈 · 链队列 · 栈与队列的协作 · 模拟时钟 · 文件事件驱动 · 异常处理

2. 场景描述

一个狭长的停车场（只有唯一一个出入口），容量为 N（N 由运行参数或配置文件指定，默认 3）。
停车场外有一条无限长的便道，供满位时等待的车辆排队。
若某辆车要离场，停在它**后面（更靠内）**的车必须先全部退出场为其让路，该车离场后，这些车再按原顺序倒回。

3. 数据结构要求（硬性）

对象 必须使用 说明
停车场 顺序栈 Parking 栈顶 = 出入口，容量 N
便道 链队列 Sidewalk 队首 = 最先等待的车
让路暂存 顺序栈 Temp 容量 N，用于临时倒出车辆
  • 三个结构均需独立封装为 .c / .h，提供 Init / Push / Pop / IsFull / IsEmpty / EnQueue / DeQueue 等标准操作。

4. 必做功能

4.1 事件输入

  • (1) 支持键盘交互：手动输入单条事件并立即看到结果。

  • (2) 支持文件批量读取事件序列 events.txt，每行一条，格式为：

  • (3) 程序必须校验事件时间的单调递增，出现时间倒流时报错并跳过该事件。

4.2 核心处理逻辑

  • (4) 到达：停车场未满 → 入栈，记录入场时间；已满 → 入便道队列，记录便道入场时间，并提示"停车场已满，请在便道等候，当前第 X 位"。
  • (5) 离开：
    • 在停车场中查找该车；若不在场内，提示"车牌 XXX 不在停车场内"，并检查便道队列（若车在便道，提示可直接离场，不入停车场）。
    • 找到后：将其上方所有车依次 Pop 到 Temp 栈，每倒出一辆打印一行提示（便于演示栈行为）。
    • 该车出栈并结算费用。
    • Temp 中的车依次倒回停车场（顺序不变）。
    • 若便道非空：队首车出队并入栈，入场时间 = 本次离开事件的时间。
  • (6) 每次事件处理后打印当前状态：停车场内车辆（按"入口 → 内部"顺序）、便道等待队列、剩余车位数。

4.3 计费

  • (7) 费率可配置（默认：2 元/小时，不足 1 小时按 1 小时计，单车单日封顶 50 元）。

  • (8) 输出结算单，形如：

  • (9) 便道等待免费（若自行设计为计费，需在报告中说明规则并由程序一致执行）。

4.4 日志与统计

  • (10) 每次操作追加写入 parking.log，含：事件时间、操作类型、车牌、处理结果。
  • (11) 程序结束时输出当日报表：入场总数、离场总数、收费总额、便道最长等待时长、平均停留时长。

4.5 健壮性

  • (12) 重复入场（同车牌未离场又到达）→ 提示并拒绝。
  • (13) 未入场车辆离场 → 提示并拒绝。
  • (14) 停车场为空时执行离场 → 提示。
  • (15) 非法车牌（空串、超长）→ 提示。

5. 选做加分项

  • [ ] 便道等待超过 30 分钟自动离场（记录为"放弃入场"）
  • [ ] 车型区分：大型车占 2 个连续车位（需处理不连续空位的情况）
  • [ ] 用哈希表按车牌快速定位车辆在栈中的位置，并与顺序查找对比 ASL
  • [ ] 支持多天连续模拟，按日生成报表

题目三：表达式求值与计算器（学号 % 3 == 2）

1. 覆盖知识点

顺序栈（双栈）· 中缀表达式转后缀 · 字符串解析 · 运算符优先级 · 错误处理 · 文件批量测试

2. 场景描述

从键盘或文件读入一行中缀算术表达式（如 3 + 4 * ( 2 - 1 ) / 2），程序完成两件事：

  1. 用运算符栈把中缀式转换成后缀式（逆波兰式）
  2. 用操作数栈对后缀式求值

要求每一步都打印出两个栈的内容——这是理解"栈如何消解运算符优先级"最直观的方式。

3. 数据定义

4. 存储与算法要求（硬性）

对象 必须使用 说明
表达式分解 字符串扫描 → Token 数组 必须支持多位数、小数、一元负号
中缀 → 后缀 顺序栈（运算符栈） 必须输出每一步的栈状态
后缀求值 顺序栈（操作数栈） 必须输出每一步的栈状态
历史记录 顺序表 或 文件 支持回看
  • 两个栈需独立封装为 .c / .h，提供 Init / Push / Pop / GetTop / IsEmpty / IsFull。

5. 必做功能

5.1 输入与词法分解

  • (1) 支持键盘输入一行中缀表达式（允许带空格），如 3 + 4 * ( 2 - 1 ) / 2。
  • (2) 词法分解：把字符串切成 Token 数组，识别数字（含多位数、小数）、运算符 + - * / % ^、括号 ( )。
  • (3) 支持一元负号：如 -3 + 5、2 * (-4) 需正确处理（需在报告中说明你的判别规则）。
  • (4) 支持变量：形如 a = 3 + 4 存入变量表，之后可用 a * 2 参与计算（变量表用顺序表实现）。
  • (5) 支持从文件 expressions.txt 批量读取表达式（每行一条），逐条求解并汇总输出。

5.2 中缀转后缀（核心考察点）

  • (6) 用运算符栈实现转换，输出后缀表达式（各元素以空格分隔）。

  • (7) 必须支持分步打印，形如：

  • (8) 运算符优先级：( < + - < * / % < ^；其中 ^ 为右结合（需在报告中说明处理方式）。

  • (9) 转换结束后若运算符栈中仍有 ( → 报"括号不匹配"。

5.3 后缀求值（核心考察点）

  • (10) 用操作数栈求值，逐步打印入栈 / 出栈过程与中间结果，形如：

  • (11) 统计并输出：Token 总数、操作数入栈次数、运算符弹出次数、总执行步数。

5.4 错误处理（必做）

  • (12) 括号不匹配（多余左括号 / 多余右括号）→ 报错并指出第几个字符
  • (13) 除数为 0 → 明确报错，不得输出 inf / NaN
  • (14) 非法字符 → 报错并指出位置
  • (15) 运算符连用（如 3 + * 4）、表达式以运算符结尾（如 3 + ）→ 报错
  • (16) 空表达式 → 提示

  • (19) 追加写入 calc.log：时间、原始表达式、后缀式、结果或错误信息
  • (20) 支持查看历史计算记录（从 calc.log 读回并表格化显示）

  3. 数据结构设计：所选结构的 ADT 定义（数据对象、数据关系、基本操作），说明为什么选它

  5. 复杂度分析：每个核心操作的时空复杂度，用表格汇总
  6. 测试方案与结果：测试用例表（输入 / 预期输出 / 实际输出 / 是否通过），含边界与异常用例

六、AI 使用情况说明（必交，缺失者不予验收）

6.1 基本原则

  • 本课程允许使用 AI 辅助学习，不允许让 AI 代写。二者的区别在于：你是否能讲清楚代码的每一行为什么这么写。
  • AI 可以是"助教"（解释概念、排查报错、启发思路），但不能是"枪手"。
  • 隐瞒使用属于学术不端；如实申报本身不会扣分。

6.2 报告中必须包含的内容（缺一不可）

(1) AI 使用声明表——逐条列出每一次求助，一行一条，不得合并概括：

序号 日期 AI 工具 用途类别 我的原始提问（完整 prompt 原文） AI 给出的关键内容 我如何验证/修改 是否采纳
1 10-08 ChatGPT C “我在 C 里用单链表删除节点，free 之后程序崩溃，这是我的代码：……” 指出应先保存 next 指针再 free 用 gdb 单步确认，改后正常 采纳

(2) 完整原始 prompt（重点）

  • 每一条求助都必须贴出你当时实际输入的完整原文，包括上下文说明、粘贴的代码片段、报错信息。
  • 形式不限：文字照抄，或聊天截图（截图必须能看清全文，长对话需分段截取）。
  • 以下写法一律视为未申报，按 0 分处理：
    • “我问了 AI 链表的写法”
    • “使用 AI 辅助完成了排序功能”
    • 只写关键词、只写主题、或事后重写的"美化版"提问
  • 若提问经过多轮追问，每一轮都要列出，并把追问的完整 prompt 一并贴出。

(3) 用途分类标注——每条记录注明属于哪一类：

类别 含义 示例
A 概念解释 “解释快速排序的分区过程”
B 报错排查 “为什么 malloc 后提示段错误”
C 代码生成 “帮我写一个链表的按值删除函数”
D 调试优化 “这段二分查找为什么死循环”
E 报告/文档润色 “帮我润色这段设计说明”

(4) AI 生成代码占比自评

  • 估算「AI 直接生成、且你基本未改动就保留的代码行数 ÷ 总代码行数」，给出百分比。
  • 列出采纳代码的具体位置：文件名 + 函数名 + 行号区间，例如 list.c : list_delete() : L88-L112。

(5) 验证与纠错记录

  • 说明你是怎么验证 AI 给出的代码的（编译、构造测试数据、gdb 单步、对拍）。
  • 至少写出 1 处 AI 给错或不适用的地方，以及你如何改正。

(6) 使用反思

  • 用了 AI 之后，哪些知识点你其实没有真正学会？列出 2~3 条。
